# Changelog

Release notes of autoreview, newest first. Unreleased changes are fragments
under `changelog.d/`; `scripts/changelog fold` moves them here.

## 0.1.0 - 2026-11-09

### Added

- `autoreview init --dir --login --pohunek-host --example` writes `config.yaml`, the example's `policy.yaml` and its prompts into a directory, creating it when absent, prints the agent profiles the policy needs, and never overwrites a file. ([#8](https://github.com/pohunekd/autoreview/issues/8))
- A repository rule can now trust only some authors: `authors.trusted` lists logins (a user as `name`, an app as `name[bot]`, matched by author type), a repository permission or both, and an untrusted author, or the author of a fork pull request who is not listed, is skipped or reviewed under the `untrusted` section from the base checkout and is never approved without the user. The class is resolved when a review is dispatched, stored with it, and logged on the `review scheduled` line. ([#34](https://github.com/pohunekd/autoreview/issues/34))
- `autoreview mcp` serves the review commands as MCP tools over Streamable HTTP, so agents can list and read reviews and, with a write token, resolve, approve and retry them. It is off until the new optional `mcp` section names the clients and the SHA-256 digests of their tokens. ([#179](https://github.com/pohunekd/autoreview/issues/179))
- `notify.routes` in `config.yaml` accepts an event name as a key next to `action`, `digest` and `log`, so a single event, such as `approved`, posts to its own Matrix room while every other event keeps the route of its level. The level still decides the mention and whether a failed message is dropped. A key that names no event, or a backend that is not configured, is refused at load with `configuration_invalid` naming `notify.routes.<key>`. ([#187](https://github.com/pohunekd/autoreview/issues/187))
- Each release ships a static Linux binary for `x86_64` and `aarch64` as `autoreview-<version>-<target>.tar.gz`, with a `.sha256` file and a build provenance attestation. The install guide makes this archive the default install path and shows how to check the checksum and the attestation. ([#222](https://github.com/pohunekd/autoreview/issues/222))

### Changed

- **Breaking:** A reviewer whose `finding_prefix` is `P` now fails the policy check, because `P` numbers the prior findings published again. Change that reviewer to another uppercase letter. ([#11](https://github.com/pohunekd/autoreview/issues/11))
- **Breaking:** Every repository rule of the policy now needs an `authors` section, and a policy without one is refused at load with `authors is required`. To keep reviewing every author as before, forks included, add `authors: {trusted: any}` to each rule. ([#32](https://github.com/pohunekd/autoreview/issues/32))
- **Breaking:** `session.name_prefix` and `session.branch_prefix` now name the pohunek sessions and reviewer branches. Set them to `github-review-` and `autoreview/review/` to keep the names of earlier releases, and change them only while no review runs, because a running review finds its session by name. A `session.branch_prefix` that cannot be part of a git ref name, or a prefix with a control character, is refused with `configuration_invalid`. `publish.signature` is published as written, so the example no longer shows a `{login}` placeholder. ([#193](https://github.com/pohunekd/autoreview/issues/193))
- The example `config.yaml` now loads as it is: its notifications and the review queue go to one placeholder `matrix` backend instead of a `none` backend that the loader refused. CI checks that every example policy loads with it. ([#36](https://github.com/pohunekd/autoreview/issues/36))
- When a rule runs several reviewers, a finding that two of them report on the same path, line and severity is published once, under the first reviewer's ID and with every reviewer's label. The review shows one summary, the first reviewer's, and one list of the validation performed without duplicates. ([#174](https://github.com/pohunekd/autoreview/issues/174))
- Published reviews are shorter: a non-blocking note shows only its heading and the `path:line` the reviewer reported (a note the verifier demoted keeps its body with the reason), and the list of validation performed is collapsed. Every reviewer request now states the summary, title and body limits from `limits`, and a Claude request also the limit of each prior-finding note. ([#175](https://github.com/pohunekd/autoreview/issues/175))
- The review host is the first host of `pohunek.hosts` whose projects serve the repository, so a repository registered on several hosts is reviewed there instead of failing with `project_route_ambiguous`. A host that fails is skipped with the warning `review host skipped` and the next host is asked, so one host outage no longer stops the reviews of repositories that other hosts serve. A repository that a trusted host also serves, for example through an `auto` project source, now runs there instead of failing, so pin untrusted repositories with `route_overrides` or keep `auto` out of their `project_sources`. ([#180](https://github.com/pohunekd/autoreview/issues/180))
- `config.yaml` accepts one Matrix backend per notification level and one for the review queue, so each level posts to its own room as the Go engine does. These backends must share `homeserver_url`, `access_token_env` and `mention_user`; a backend that differs is refused with the first route key, in the order `action`, `digest`, `log` and review queue, whose backend differs from an earlier one. ([#185](https://github.com/pohunekd/autoreview/issues/185))

### Fixed

- Reviews created within the same second are listed and resumed in the order they were created, and pruning compares the last update with the retention cutoff by time, so a review at the boundary is no longer kept or deleted by mistake. ([#120](https://github.com/pohunekd/autoreview/issues/120))
- An approval sent right after the approval request is accepted instead of failing with `review_not_awaiting_approval`, because the review is stored as waiting before the request is sent. When the approval request cannot be delivered, the review keeps waiting and `autoreview awaiting` lists it, instead of failing the review. ([#143](https://github.com/pohunekd/autoreview/issues/143))
- A review queue routed only to `none` backends is refused at load with `notify.review_queue.backends: none is not supported for the review queue`, and an empty list with `notify.review_queue.backends: must name at least one backend`, in place of the unrelated `invalid Matrix queue room`. ([#182](https://github.com/pohunekd/autoreview/issues/182))
- Discovery no longer fails when a label search finds no pull request or returns a `null` field or list entry, and a `null` value in a GitHub or pohunek response field is read as the Go engine reads it. ([#192](https://github.com/pohunekd/autoreview/issues/192))
- A reviewer output that breaks one of the engine checks (findings list, pull request and head, summary length, finding and test counts, a finding's id, side, line, path, title, body, confidence or severity, or a test's text) gets a fresh reviewer run up to the run limit instead of failing the review as `artifact_invalid`, and the log names the failed check. ([#196](https://github.com/pohunekd/autoreview/issues/196))
- The example policies no longer route `credential_invalid` and `credential_expiring`, events the engine does not know. The docs no longer describe `--env-file`, `prune-branches`, webhook backends, several backends per level or routes to `none`, and say that a route to a `none` backend is refused at load. ([#209](https://github.com/pohunekd/autoreview/issues/209))
- An unreachable notifier no longer stalls discovery: a discovery pass saves its state and queues due reviews first, then sends each notification once, skips the rest of a level after one fails at any level, sends nothing after a shutdown, and logs every undelivered one as `discovery notification dropped` without resending it. Every retry of a step is logged as `step failed, retrying` with the step, the error code and the delay. ([#210](https://github.com/pohunekd/autoreview/issues/210))
- An unreachable notifier no longer holds or fails a review: each notification of a review gets one attempt, and an undelivered one is logged as `review notification dropped` while the review goes on without resending it. `autoreview review-queue` posts its digest once and fails with the backend's error code, logged as `review queue digest dropped`, instead of retrying for the whole step budget. ([#212](https://github.com/pohunekd/autoreview/issues/212))
- A reviewer session whose worker pohunek reports as lost during the start now fails with the retryable code `pohunek_session_lost`, logged with pohunek's loss cause, instead of `session_identity_invalid` or `pohunek_session_cleanup_failed`. The explanations of `pohunek_base_fetch_timeout` and `pohunek_base_fetch_authentication_failed` name the SSH agent, and the troubleshooting runbook gains checks for inotify watches, non-interactive Git access and fetching over HTTPS. ([#213](https://github.com/pohunekd/autoreview/issues/213))

### Security

- The `gh` and `pohunek` processes that autoreview starts no longer inherit any `AUTOREVIEW_*` variable, any variable named by a `*_env` key or the Go engine's `MATRIX_ACCESS_TOKEN`; a `gh` call still gets the token of its credential as `GH_TOKEN`. ([#184](https://github.com/pohunekd/autoreview/issues/184))
