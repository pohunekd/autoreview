`autoreview validate` refuses a store whose directory or files grant the group or other users any access, with `configuration_invalid` naming `store.path` and the `chmod` that fixes each path; it changes no mode itself. autoreview creates a missing store database with mode 0600 whatever the umask, `autoreview init` creates its `--dir` with mode 0700 when the store lies inside it, and `scripts/setup` runs `init` under `umask 077` and sets `UMask=0077` in its user units. Before the upgrade, make an existing store private as its owner, or `validate` stops, and with it `scripts/setup` (exit code 9) and `deploy/install.sh` (exit code 4): on a setup deployment made under the common umask 022, whose 0755 directory and 0644 store let other local users read the review history, run `chmod 700 DIR` and `chmod 600 DIR/autoreview.db*` with the `--dir` you gave setup (for example `~/autoreview`); for a store that a command run by hand created (install path a, or a path b store first opened with `sudo -u autoreview`), run `sudo -u autoreview chmod 600 /var/lib/autoreview/autoreview.db*`.
