A Claude reviewer run that Claude Code ends on the rate or usage limit of its model account (a result message with `is_error`, subtype `success` and `api_error_status` 429) now fails with `reviewer_usage_limited` instead of `review_wrapper_invalid`. The reviewer is not run again inside the review; the scheduler tries the review again after each delay of the new required key `schedule.usage_limit_retry_delays_seconds` (1 to 24 non-decreasing values, each from 1 to 21600 seconds; the example's `[900, 1800, 3600, 3600, 3600, 3600, 3600]` covers 5 h 45 min) without spending `schedule.retry_delays_seconds`, and notifies only on the first limited attempt in a row and when it stops. Add the key to `config.yaml` in the same window as the new binary, never before, because an earlier release refuses it; on a converted deployment add `HERMES_PR_REVIEW_USAGE_LIMIT_RETRY_DELAYS_SECONDS_JSON` for `scripts/env-to-config`. Codex output names no structured limit, so Codex reviewers are unchanged.
