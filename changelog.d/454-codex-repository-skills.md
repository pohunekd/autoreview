Codex reviewer runs now refuse a `checkout: head` pull request that adds or changes a repository skill (`.agents/skills/` or `.codex/skills/`, compared on disk with the trusted base, so also as a link, an ignored file, a nested repository or a file that an index flag hides from git) before Codex starts, with `refused:repository_skills` before the exit line, and pass `skills.include_instructions=false`: before, Codex 0.167.0 loaded those skills without host trust, listed them on every turn and injected the whole `SKILL.md` of a skill that the prompt names, so a pull request could add instructions to its own review. The engine stops such a review at the first refused attempt with the new code `review_head_skills_refused`, which is not retried, and publishes nothing (#457); a `checkout: base` review and a head whose skills match the trusted base run as before. The change reaches a review host only when its profiles are installed again with `autoreview profiles install`.
